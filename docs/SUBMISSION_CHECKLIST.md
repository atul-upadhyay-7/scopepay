## Before release

- [ ] Owner runs the Spring Boot rebuild from a clean clone on his laptop (Java 21, Maven, Node 22+, local PostgreSQL per docs/LOCAL_RUN.md) with the documented configuration. Verify real AI, saved review, sandbox approval/capture, receipts timeline/ledger, and independent seller receipt. (The earlier Node prototype passed this on Oct 16, 2026; the rebuilt stack re-verifies live.)
- [ ] Owner confirms entry identity, age-of-majority eligibility, residence, conflicts and solo/team/organization status.
- [ ] Owner reviews authorship, third-party rights and applicable dependency/API terms. Do not describe the project as unaided work. Do not certify rights merely because code exists.
- [x] Owner chose MIT on October 16, 2026; root LICENSE added and pushed (commit 5df7266, holder: Atul Upadhyay), GitHub detects MIT. Keep dependency notices; license only rights the owner holds.
- [ ] Complete a dependency/asset notice review and history-wide credential scan before public release. Remove unnecessary account-specific transaction IDs from public copy, keeping useful verification method/results.
- [ ] Make the repository public only after the owner's explicit public-release decision (the license step is done; publication is not). Re-privatizing cannot recall copies/forks.
- [ ] Resolve judge access. Local setup is permitted instead of hosting, but judges still need an actually working build and all necessary access. Do not publish reusable secrets in the repo or video. Verify a supported private credential/access route with organizers, or confirm an accepted own-credentials route. Mere instructions to request new accounts have not been verified as unrestricted access.
- [ ] Do not internet-expose this local app. A hosted option would need separate security work and free-service availability checks.
- [ ] Record an English video under 3 minutes showing the actual laptop app and full sandbox flow. Use no copyrighted music, unrelated logos or personal data. Resolve any permission ambiguity around third-party UI/trademarks before uploading; the rules' trademark clause is broad.
- [ ] Owner approves final video and uploads as PUBLIC YouTube, not unlisted. Verify signed-out playback and duration.
- [ ] Review final Devpost title, tagline, story, tools, repo/video/demo/testing links, images, participant details and every consent/form answer together. Do not invent field labels or answer unseen questions.
- [ ] Owner explicitly approves the final submission. Verify the entry is submitted, not merely saved as a draft, and save its actual confirmation/link.
- [ ] Keep judge access available through the judging deadline. Arrange that follow-through before promising it.

## Consent review is not a checkbox default

The official rules create a contract on entry. They include ownership and eligibility warranties, a judging license, publicity/name/likeness/voice use, personal-information handling, releases/indemnities, dispute terms and possible prize/tax paperwork. The owner must read and choose; no acceptance is preselected here. This is a practical checklist, not legal advice.

## Scope integrity

Market as an evidence-linked scope-review and sandbox checkout prototype. Do not claim escrow, autonomous charging, production safety, verified commercial impact, universal AI accuracy, real clients or actual revenue. Optional sponsor tools are not required; claim only tools actually used.
